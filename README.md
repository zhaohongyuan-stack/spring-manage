# FrManage — 酒店进销存管理后端

酒店物资进销存（采购 → 入库 → 库存 → 领用出库）后端服务，基于 Spring Boot 3 提供 REST API，配套 Swagger 文档与单元/集成测试。

---

## 1. 技术栈与版本

| 组件 | 版本 | 说明 |
|------|------|------|
| Java | **17** | `pom.xml` 中 `java.version` |
| Spring Boot | **3.2.12** | 父工程版本 |
| Maven | **3.9.16** | 通过项目内 `mvnw` 包装器自动下载 |
| MyBatis-Plus | **3.5.7** | ORM，主键自增、下划线转驼峰 |
| PostgreSQL | **建议 14+** | 主数据库（驱动由 Spring Boot 管理） |
| Redis | **建议 6+** | 业务单号原子递增 |
| SpringDoc OpenAPI | **2.5.0** | Swagger UI / OpenAPI 文档 |
| Lombok | 随 Spring Boot | 实体与 DTO 简化 |
| Spring Security | 随 Spring Boot | 当前为**临时全放行**，JWT 待接入 |

**项目坐标**：`com.fengrui:FrManage:0.0.1-SNAPSHOT`

## 2. 环境要求

部署前请确认本机已安装并启动：

1. **JDK 17**（`java -version`）
2. **PostgreSQL**（默认库名见下文配置）
3. **Redis**（采购/入库/领用单号依赖 Redis，未启动会导致创建单据失败，错误码 `50301`）

> 无需单独安装 Maven，使用仓库根目录的 `mvnw.cmd`（Windows）或 `./mvnw`（Linux/macOS）即可。

## 3. 快速部署（新人 10 分钟上手）

### 3.1 克隆与进入项目

```powershell
cd D:\project\javaProjrct\FrManage
```

### 3.2 创建数据库

在 PostgreSQL 中执行：

```sql
CREATE DATABASE hotel_inventory
    ENCODING 'UTF8'
    LC_COLLATE 'zh_CN.UTF-8'
    LC_CTYPE 'zh_CN.UTF-8'
    TEMPLATE template0;
```

（Windows 环境若排序规则不同，可使用默认 `CREATE DATABASE hotel_inventory;`）

### 3.3 初始化表结构

完整建表 SQL 见仓库内 **[测试开发使用版本.md](./测试开发使用版本.md)**（按模块划分：`user`、`department`、`supplier`、`product`、`purchase`、`purchase_item`、`inbound`、`inbound_item`、`receive`、`receive_item`、`inventory`、`inventory_record`）。

**注意（PostgreSQL 与文档差异）**：

- 实际运行库为 **PostgreSQL**，文档中部分 DDL 为 MySQL 写法，落地时需调整：
  - 用户表名 `user` 在 PostgreSQL 中需加双引号：`"user"`
  - `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY` 或 `SERIAL`
  - `tinyint` → `smallint`
  - 采购/入库/领用状态字段在代码中统一映射为列名 **`status`**（非文档中的 `purchase_status` / `inbound_status` / `receive_status`）
- 建表完成后，在 `hotel_inventory` 库中**依次执行** `sql/` 目录下脚本：

```text
sql/20260616_add_purchase_no_unique_index.sql
sql/20260616_add_inbound_no_unique_index.sql
sql/20260616_add_receive_no_unique_index.sql
sql/20260617_add_product_name_spec_unique_index.sql
sql/20260617_alter_user_dept_id_nullable.sql   # 采购员/仓管等职能角色 dept_id 可空
sql/integration_test_seed_data.sql             # 链路测试基础数据
```

### 3.4 修改配置（按需）

主配置文件：**`src/main/resources/application.yml`**

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/hotel_inventory
    username: postgres
    password: 123456          # 请按本机环境修改
  data:
    redis:
      host: localhost
      port: 6379
      database: 0

server:
  port: 8080
```

### 3.5 启动 Redis

```powershell
# 示例：若已安装为 Windows 服务
redis-server
# 或
net start Redis
```

验证：`redis-cli ping` 应返回 `PONG`。

### 3.6 编译并启动应用

```powershell
.\mvnw.cmd clean package -DskipTests
.\mvnw.cmd spring-boot:run
```

启动成功后：

| 用途 | 地址（直连后端） | 地址（经 Nginx 80 端口） |
|------|------------------|--------------------------|
| REST API | http://localhost:8080/api/v1/... | http://localhost/api/v1/... |
| Swagger UI | http://localhost:8080/swagger-ui.html | http://localhost/swagger-ui.html |
| OpenAPI JSON | http://localhost:8080/v3/api-docs | http://localhost/v3/api-docs |

### 3.7 通过 Nginx 反向代理（可选）

配置文件：`d:\nginx-1.24.0\conf\nginx.conf`（已将 `/api/` 及 Swagger 代理到 `127.0.0.1:8080`）。

```powershell
# 先启动 Spring Boot，再重载 Nginx
cd D:\nginx-1.24.0
.\nginx.exe -t          # 校验配置
.\nginx.exe -s reload   # 或首次启动 .\nginx.exe
```

前端联调时，请求基地址使用 `http://localhost/api/v1` 即可，无需写 `:8080`。

### 3.8 验证数据库连接（可选）

```powershell
.\mvnw.cmd test -Dtest=DatabaseConnectionTest
```

## 4. 配置说明汇总

### 4.1 应用服务

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `server.port` | `8080` | HTTP 端口 |
| `spring.application.name` | `FrManage` | 应用名 |

### 4.2 PostgreSQL

| 配置项 | 默认值 |
|--------|--------|
| `spring.datasource.driver-class-name` | `org.postgresql.Driver` |
| `spring.datasource.url` | `jdbc:postgresql://localhost:5432/hotel_inventory` |
| `spring.datasource.username` | `postgres` |
| `spring.datasource.password` | `123456` |

**MyBatis-Plus**：

- `map-underscore-to-camel-case: true` — 数据库下划线字段映射 Java 驼峰
- `id-type: auto` — 主键数据库自增

### 4.3 Redis

| 配置项 | 默认值 |
|--------|--------|
| `spring.data.redis.host` | `localhost` |
| `spring.data.redis.port` | `6379` |
| `spring.data.redis.database` | `0` |

**Redis Key 约定（单号生成，按日递增，过期 2 天）**：

| Key 模式 | 生成单号格式 | 用途 |
|----------|--------------|------|
| `purchase_no:yyyyMMdd` | `CG-yyyyMMdd-001` | 采购单 |
| `inbound_no:yyyyMMdd` | `RK-yyyyMMdd-001` | 入库单 |
| `receive_no:yyyyMMdd` | `LY-yyyyMMdd-001` | 领用单 |

### 4.4 安全策略（当前阶段）

`SecurityConfig` 中 `TEMPORARY_PERMIT_ALL = true`：**所有 API 临时无需登录**，便于联调。  
正式环境需关闭该开关并接入 JWT；目标权限见 **[接口权限清单.md](./接口权限清单.md)**。

业务层已通过 `RoleAuthSupport` 做角色校验（如采购审批、入库验收、领用出库等）。`admin` 与 `gm` 视为超级管理员。

## 5. 数据库表一览

共 **12 张业务表**（均在 `public` schema）：

| 表名 | 说明 |
|------|------|
| `"user"` | 系统用户（角色、部门、密码 BCrypt） |
| `department` | 部门树 |
| `supplier` | 供应商 |
| `product` | 商品主数据 |
| `purchase` | 采购单头 |
| `purchase_item` | 采购明细（含 `received_quantity` 累计收货） |
| `inbound` | 入库单头 |
| `inbound_item` | 入库明细 |
| `receive` | 领用单头 |
| `receive_item` | 领用明细 |
| `inventory` | 库存（主键 `product_id`，移动加权平均成本） |
| `inventory_record` | 库存流水 |

### 5.1 核心状态枚举（代码见 `common.enums`）

**采购单 `purchase.status`**

| 值 | 含义 |
|----|------|
| 1 | 待审批 |
| 2 | 已通过（待采购） |
| 3 | 采购中 |
| 4 | 已入库 |
| 5 | 已取消 |
| 6 | 已驳回 |

**入库单 `inbound.status`**：1 待验收 → 2 已验收  

**领用单 `receive.status`**：1 待审批 → 2 待出库 → 3 已出库 / 4 已取消 / 5 已驳回  

**库存流水 `inventory_record.change_type`**：1 正常入库 / 2 正常出库 / 3 食材直拨 / 4 期初初始化 / 5 盘点调整

### 5.2 系统角色（`user.role`）

`dept_employee`、`dept_head`、`purchaser`、`warehouse_keeper`、`finance`、`gm`、`admin`

| 模块 | 基础路径 | Controller |

接口明细、请求示例见 **Swagger** 或 **[测试开发使用版本.md](./测试开发使用版本.md)**。

### 6.1 标准业务流程（快乐路径）

```text
创建采购申请(1) → 部门负责人审批(2) → 采购员确认(3)
    → 仓库创建入库单(待验收) → 部门负责人验收(库存+、采购→4)
    → 员工领用申请(1) → 部门负责人审批(2) → 仓库确认出库(3、库存-)
```

链路集成测试类：`PurchaseToReceiveHappyPathIntegrationTest`（见下文测试章节）。

## 9. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 创建采购/入库/领用返回 `50301` | Redis 未启动 | 启动 Redis 后重试 |
| `40301 无权操作` | 操作人角色不匹配 | 检查 `user.role`；`admin`/`gm` 可全流程 |
| 采购确认失败 | 采购单状态不是 `2` | 先完成审批 |
| 入库验收后采购仍为 `3` | 未全部收货完成 | 入库数量需累计达到采购数量 |
| 集成测试 Skipped | 缺少用户 100/101/102 等 | 按 8.3 节补齐数据 |
| Swagger 打不开 | 端口占用或应用未启动 | 检查 8080 端口与启动日志 |
